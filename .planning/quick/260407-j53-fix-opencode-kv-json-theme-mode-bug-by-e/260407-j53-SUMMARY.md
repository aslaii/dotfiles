# Phase 260407-j53 Plan 01: Fix OpenCode kv.json theme_mode Bug Summary

Extended `scripts/sync-ai-cli-theme.sh` with an `update_opencode_theme()` jq writer and added an `opencode()` shell wrapper in `macos/zsh/zsh/functions.zsh` so OpenCode's `~/.local/state/opencode/kv.json` `theme_mode` is rewritten to match macOS appearance before every TUI launch — mirroring the existing claude/gemini/codex sync pattern, zero new files, zero changes to `opencode/tui.json`.

## What Changed

### `scripts/sync-ai-cli-theme.sh` (+19 lines)

1. Added `opencode_mode="dark"` to the Dark branch and `opencode_mode="light"` to the Light branch of the existing `defaults read -g AppleInterfaceStyle` if/else (lines 9 and 14 of the new file).
2. Added a new `update_opencode_theme()` function (lines 59–73) that:
   - Targets `$HOME/.local/state/opencode/kv.json`

   - Uses the established `mktemp` + `jq` + `mv` atomic pattern (same as `update_claude_theme`)
   - Writes `.theme_mode = $mode` where `$mode` is `"dark"` or `"light"`
3. Added `update_opencode_theme` invocation at the bottom of the script (line 78), after `update_claude_theme`.

### `macos/zsh/zsh/functions.zsh` (+5 lines)

To prove the new function is correct in isolation, I executed its body directly:

```bash
$ bash -c 'set -euo pipefail

if [[ ! -f "$config_path" ]] || ! command -v jq >/dev/null 2>&1; then
```

## Deferred Issues — RESOLVED IN-LINE BY ORCHESTRATOR

**DEF-1 — `update_codex_theme()` fails on symlinked `~/.codex/config.toml`** (pre-existing) — **RESOLVED in commit `f38f576`**

Discovered during functional verification. The pre-existing `update_codex_theme()` used `sed -i ''` directly on `~/.codex/config.toml`, which on dotfiles installs is symlinked to `dotfiles/codex/config.toml`. BSD sed refuses in-place editing on symlinks (`sed: ...: in-place editing only works for regular files`), and `set -euo pipefail` aborted the script before any subsequent `update_*_theme` function — including the new `update_opencode_theme` — could run.

The orchestrator escalated this from a deferred item to a hotfix because **the OpenCode bug fix had zero user-visible effect until codex was unblocked**, defeating the entire purpose of the task. Fixed via a follow-up atomic commit `f38f576` (`fix(codex): resolve symlink before sed to support dotfiles symlinked configs`):

```bash
# Added before the sed call in update_codex_theme():
if [[ -L "$config_path" ]]; then
  config_path="$(python3 -c 'import os, sys; print(os.path.realpath(sys.argv[1]))' "$config_path")"
fi
```

`python3` is shipped with macOS by default and `os.path.realpath` resolves arbitrary symlink chains portably (no GNU `readlink -f` dependency, no perl heredoc).

**End-to-end verification after `f38f576`:**
```bash
$ bash scripts/sync-ai-cli-theme.sh
$ echo "EXIT: $?"
EXIT: 0
$ jq -r .theme_mode ~/.local/state/opencode/kv.json
light   # was "dark" before the script ran; macOS is currently Light
```
The codex symlink itself is preserved (sed wrote to the resolved real path, not the link). The new `update_opencode_theme` now runs to completion. The user-visible bug is fully fixed.

**Tooling note on `f38f576`:** the orchestrator used the `Edit` tool to apply the fix, which triggered the project's `shfmt` pre-commit hook to auto-tabify the entire file. Functional change is correct (+6 lines of new logic) but the diff stat shows `+59 / -52` because of the whitespace conversion. The file is now consistent with the project's actual `shfmt` config (tabs). One-time cleanup; future edits should be diff-clean.
