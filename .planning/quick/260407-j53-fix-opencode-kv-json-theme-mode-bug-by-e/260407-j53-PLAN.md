<objective>
Fix the OpenCode TUI theme_mode persistence bug where stale `theme_mode` in `~/.local/state/opencode/kv.json` overrides live terminal-background detection on every launch. We mirror the exact pattern already used for codex/gemini/claude: extend the central `sync-ai-cli-theme.sh` script to write the correct `theme_mode` into kv.json, and add an `opencode()` shell wrapper that fires the sync before invoking the real binary.

Purpose: Restore parity between Ghostty and OpenCode theme rendering when macOS appearance switches (Auto/Light/Dark), without modifying OpenCode itself or the kv.json file in the dotfiles repo (it's runtime state, not tracked).
Output: Two surgically-extended existing files. Zero new files. Zero changes to opencode/tui.json.
</objective>

  local config_path="$HOME/.claude/settings.json"
  local tmp_file

  if [[ ! -f "$config_path" ]] || ! command -v jq >/dev/null 2>&1; then

  fi

    "$config_path" >"$tmp_file"
